How to read these comparisons

The values are the ones the main page shows, fitted from public measurements taken on the same tasks. One model is cheaper or higher than the other at an effort level when the fitted difference puts it ahead with at least 84 % probability, the level of the intervals shown everywhere on the site; otherwise the two are level within the uncertainty. A match is the cheapest setting of the other model that the first does not out-score at that level. Costs are what a whole task cost, as each source measured it (the run's actual spend, cache included), not the price per token. So the cost already counts how many tokens each model uses: a model with a lower price per token can still cost more per task if it writes many more tokens.
